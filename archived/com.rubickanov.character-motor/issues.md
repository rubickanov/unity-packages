## Minor (conventions / shortcomings)

- **SlopeSlideModule never activates with default config** — `Runtime/Modules/SlopeSlideModule.cs:22` and `Runtime/Modules/GroundDetectionModule.cs:36` — `SlopeSlideModule.Simulate` early-returns unless `State.IsGrounded && State.GroundAngle > _slideAngle` (default `_slideAngle = 46`). But `GroundDetectionModule` sets `State.IsGrounded = angle <= _maxSlopeAngle` (default `_maxSlopeAngle = 46`). With the two default thresholds equal, any slope above 46° is flagged as airborne (so `IsGrounded == false`) and any slope at/below 46° fails the `GroundAngle > _slideAngle` test, so on a real motor wired with both default modules the slide force is never applied. The window only opens when `_slideAngle` is configured strictly below the ground detection's `_maxSlopeAngle`. Either document the dependency or default `_slideAngle` below the ground slope limit.

- **README omits SlideModule** — `README.md:21-31`, `README.md:232-244` — `Runtime/Modules/SlideModule.cs` (priority 12) is a public built-in module but appears in neither the Architecture diagram nor the "Built-in Modules" table. The README lists 9 modules; the package ships 10. Add SlideModule so the documented module set matches the code.

- **IStatefulModule doc names SprintModule as not needing state, but it does** — `Runtime/Interfaces/IStatefulModule.cs:6` — the XML comment says "Modules without meaningful state (e.g. SprintModule) do not need this." However `SprintModule` implements `IStatefulModule` and serializes `_rampProgress` (`Runtime/Modules/SprintModule.cs:11,74-82`).
