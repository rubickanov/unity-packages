## Critical (correctness / bugs)

- **`TryGetBest`/`TopN` dereference a possibly-null `Items`** — `Runtime/Core/EQSQueryResult.cs:22` (and `:34`) — `EQSQueryResult` is a struct, so `default(EQSQueryResult)` has `Items == null`. `TryGetBest` does `if (Items.Count > 0)` and `TopN` does `if (Items.Count == 0 ...)`, both of which throw `NullReferenceException` on a default-valued result. This is concretely reachable: `EQSQueryDebuggerEditor.OnInspectorGUI` (`Editor/EQSQueryDebuggerEditor.cs:27`) calls `result.TryGetBest(out var best)` on `debugger.LastResult`, which is `default` until `RunQuery()` is invoked — so simply selecting a freshly-added `EQSQueryDebugger` in the Inspector throws. (Note line 25 of that editor already null-guards with `result.Items?.Count`, proving the null case is expected.) Fix: guard `Items == null` inside `TryGetBest`/`TopN`, or initialize the result/field to an empty-items value.

- **`GridGenerator` infinite loop when `_spacing <= 0`** — `Runtime/Generators/GridGenerator.cs:28-30` — the nested `for (float x = -_halfExtent; x <= _halfExtent; x += _spacing)` loops never advance (or run backwards) if `_spacing` is `0` or negative, hanging the editor/runtime. `_spacing` is a serialized field with no validation, so a user can set it to `0` in the Inspector. `CircleGenerator` guards `_pointCount <= 0` (`CircleGenerator.cs:29`); `GridGenerator` has no equivalent guard. Fix: early-return (or clamp) when `_spacing <= 0`.
