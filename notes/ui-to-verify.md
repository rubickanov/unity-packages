# com.rubickanov.ui: что проверить

Пункты аудита 2026-09-24 (пакет 2.1.1), в которых нет уверенности. Уверенные баги и чистка исправлены в 2.2.0.
Каждый пункт: что подозреваем, как проверить, что делать, если подтвердится.

## Поведение, которое надо проверить руками или отдельным тестом

1. **Тултип залипает, если элемент удалили из дерева.**
   `PopupManipulator` закрывает попап на `PointerLeaveEvent` элемента. Если элемент под курсором убрали из панели
   (`BindList` пересобрал строку, `Clear` списка), событие, скорее всего, не придёт: элементу без панели UI Toolkit
   событий не шлёт.
   Проверка: тултип на строке списка, навести, очистить список, увести курсор.
   Если подтвердится: в манипуляторе подписаться на `DetachFromPanelEvent` таргета и закрыть попап.

2. **Скрытый world-попап держит ввод.**
   Пока якорь за камерой, попап скрыт (`display: none`), но открыт: интерактивный держит pointer capture, с Escape
   съедает `Back()`. Может, так и задумано (маркер вернётся в кадр).
   Проверка: world-попап с кнопкой, развернуть камеру, нажать Escape и посмотреть курсор.
   Если это баг: отпускать capture и back handler на время скрытия или не считать скрытый попап интерактивным.

3. **Unregister вью, пока её клон живёт в попапе.**
   `CreateDetached` клонирует дерево из `UxmlCache` зарегистрированной вью. `Unregister` отпускает хэндлы кэша. С
   каталогом это ничего не меняет, а с Addressables-лоадером выгрузка бандла может снять стили, на которые ссылается
   клон.
   Проверка: Addressables-лоадер, вью как контент попапа, `Unregister` при открытом попапе.
   Если подтвердится: считать ссылки на кэш и отпускать его после последнего клона.

4. **Guard'ы в двусторонних биндингах, вероятно, лишние.**
   `if (field.value != v) field.value = v;` в `BindTextField` / `BindSlider` / `BindToggle` / `BindDropdown`.
   `BaseField.value` сам не шлёт `ChangeEvent` при равном значении, но наверняка это видно только по исходникам
   конкретных контролов (`Slider` клампит, `DropdownField.index` идёт через `choices`).
   Проверка: убрать guard'ы и прогнать тест на двусторонний биндинг в панели с живыми событиями.

5. **Строки списка при исключении в фабрике view model.**
   Если `createViewModel` бросит посреди `Reconcile` в `BindList`, часть старых строк не уничтожится и выпадет из
   `_rows`, оставшись в контейнере и в `_children`. Следующий `Reconcile` их не увидит: дубли на экране.
   Проверка: тест с фабрикой, бросающей на N-м элементе после `Reset`.
   Если подтвердится: собрать новые строки до изменения состояния или откатывать при ошибке.

6. **Глиф `✕` у кнопки закрытия.**
   `PopupInstance` пишет в кнопку U+2715. В шрифте проекта его может не быть: будет квадрат.
   Проверка: открыть попап с `CloseButton` в игре со своим шрифтом.
   Если подтвердится: иконка через USS-класс `popup-close` (background-image) вместо текста.

## Упрощения, которые зависят от вкуса

7. **Циклы кадров через UniTask** в `SpinnerHost` (вращение) и `PopupHost` (followers) можно заменить на
   `schedule.Execute(...).Every(0)`: планировщик UI Toolkit сам останавливается, когда элемент вне панели, и не нужен
   `CancellationTokenSource`. Минус: другой тайминг (апдейт панели, а не PlayerLoop), для followers это может дать
   отставание на кадр от камеры.

## Не покрыто тестами

- `PopupManipulator`: наведение, задержка, уход курсора. EditMode-тесту нужна панель с живыми pointer-событиями.
- `RunFollowLoop`: что исключение одного попапа не останавливает остальных. Нужен PlayerLoop (PlayMode-тест).

## Дублирование и лишние классы в попапах

Разбор 2026-09-24 (пакет 2.2.0). Ниже то, что можно выкинуть или слить, без оглядки на текущих потребителей.

### Уверенное

8. **Кнопка с `closesOnClick: false` мёртвая.** В `PopupInstance` обработчик кнопки только вызывает `Close`, если
   `closes`. Без закрытия клик никуда не уходит: события наружу нет, у `Button` нет ни `name`, ни `id`, подписаться
   снаружи нельзя. `PopupCloseTriggers.ActionButton` это вторая ручка того же самого (а `closesOnClick` и так `true` по
   умолчанию).
   Что делать: либо убрать оба (кнопка всегда закрывает), либо дать настоящий колбэк / `ButtonClicked(id)` и убрать
   `ActionButton`.

9. **`IPopupHostCallbacks` это лишняя прослойка.** Internal-интерфейс с одной реализацией (`PopupHost`, семь явных
   членов), тесты и фейки его не используют. `PopupInstance` может брать `PopupHost` напрямую.

10. **Диалоги дублируют попапы.** `IDialogService` / `DialogService` / `DialogBuilder` / `DialogResult`:
    `DialogBuilder` это `PopupBuilder` с переименованными методами, `DialogResult` это `PopupResult` без `Reason`.
    Своей логики в `DialogService` только маппинг «закрыт не кнопкой → последняя кнопка» и пресеты `Confirm`/`Alert`.
    Что делать: extension-методы над `IPopupService` (`CreateDialog` возвращает настроенный `PopupBuilder`, маппинг
    результата там же), без отдельного сервиса и регистрации в DI. Ломает публичный API → major.

11. **`RemovePopup(manipulator)`** это однострочная обёртка над `RemoveManipulator`. Убрать.

### Архитектурное: два стека попапов

12. **Слой Popup в `UIService` и `PopupHost` делают одно и то же.**
    - `UIService`: `_popupStack`, `HideTop`, back handler, pointer capture для вью на слое Popup.
    - `PopupHost`: свой список открытых, свой Escape/Back, свой capture, плюс размещение, клик снаружи и `View` как
      контент.

    Швы от этого:
    - вью, которая живёт только как контент попапа, всё равно объявляет `Layer` и проходит `Register`;
    - `PopupHost` принимает `IUIService`, но контент-вью создаёт только через конкретный `UIService`, иначе
      `NotSupportedException`: интерфейс там фикция;
    - «кто держит ввод и получает Back» считается в двух местах, которые договариваются через общий back-стек.

    Что делать: оставить одну систему. Попап-вью открывается как модальный попап с контентом по центру через
    `PopupHost`, а слой Popup и `_popupStack` уходят из `UIService`. Самый крупный рефакторинг, сначала описать API.

### На вкус

13. **`PopupConfig` и `PopupBuilder`**: два публичных API для одного и того же, билдер задаёт по одному полю на метод.
    Оставить публичным одно: либо билдер (конфиг internal), либо конфиг с object initializer без билдера.

14. **`PopupContentContext`** можно свести к `IPopupHandle`, который контент-вью получает напрямую. Заодно
    `IPopupHandle : IDisposable` и тогда `ModalHandle` не нужен.

15. **`SpinnerHost`** по сути пассивный попап на overlay без кнопок, его можно сделать пресетом. Выигрыш
    небольшой.

### Проверено и оставляем

`PopupPlacement`, пары sync/async `Hide`, `TooltipExtensions` (тонкий пресет, так и надо), `SceneViewScopeService`
(на нём `RegisterViewsOperation` в `ui.loading`).
