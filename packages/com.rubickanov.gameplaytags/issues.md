# Audit findings — com.rubickanov.gameplaytags

Generated by automated review.

## Minor (conventions / shortcomings)

- **`Matches` only guards the lower index bound, can throw `IndexOutOfRangeException`** — `Runtime/GameplayTagRegistry.cs:210-221` — `Matches(tag, parent)` checks `tag.Index <= 0 || parent.Index <= 0` but never checks the upper bound before indexing `_parents[current]`. A `GameplayTag` whose index is `>= _parents.Count` (a value resolved against a larger registry, or a cached tag after `Uninstall()` + `Install()` with a smaller tag set — the exact "stale" scenario the docstring at line 46 warns about) causes the walk `current = _parents[current]` to throw `IndexOutOfRangeException`. This crash propagates through the public surface `GameplayTag.Matches`, `GameplayTagContainer.HasTag`, and all `HasAll`/`HasAny` overloads. The documented stale-value caveat implies wrong results, not an uncaught exception. Add an upper-bound guard (`tag.Index >= _parents.Count` → return false) so misuse degrades gracefully.

- **Code generator can emit duplicate identifiers for case-differing sibling tags** — `Editor/GameplayTagsGenerator.cs:169-185` (`SanitizeIdentifier`) and `:139-167` (`WriteNode`) — `TagPathRegex` permits segments starting with either case (e.g. `Damage.fire` and `Damage.Fire` are two distinct registry tags under `StringComparer.Ordinal`). `SanitizeIdentifier` runs `ToPascalCase`, which uppercases the first letter, so both collapse to `Fire`. `WriteNode` then emits two `public static readonly GameplayTag Fire = ...` members in the same scope, producing a generated `.cs` file that does not compile, with no detection or warning at generation time. Either detect identifier collisions and report them, or make the transform injective.
