# Audit findings — com.rubickanov.config

Generated by automated review.

## Critical (correctness / bugs)

- **Addressables handle leaked on cancellation or load failure** — `Runtime/AddressablesAssetLoader.cs:14-20` — `LoadAsync` does `var handle = Addressables.LoadAssetAsync<T>(address); await handle.WithCancellation(ct);`. If `ct` is cancelled, `WithCancellation` throws `OperationCanceledException`; if the address is invalid the handle faults and the awaiter rethrows the operation's exception. In both cases the method returns/throws before the handle is handed back to the caller as a release token, so `Release` is never called and the Addressables `AsyncOperationHandle` (and any asset it eventually loads) is leaked. Addressables requires releasing even faulted handles. Fix: wrap the await in try/catch and `Addressables.Release(handle)` on any exception before rethrowing (or release the faulted/cancelled handle in a finally that runs only on the failure path).

## Minor (conventions / shortcomings)

- **`ConfigDatabase.Get(null)` throws instead of returning null** — `Runtime/ConfigDatabase.cs:23-31` — the XML doc states "Returns null if not found", but passing a `null` id reaches `Dictionary<string,TData>.TryGetValue(null, ...)`, which throws `ArgumentNullException`. Either guard `string.IsNullOrEmpty(id)` and return null, or document that `id` must be non-null.
