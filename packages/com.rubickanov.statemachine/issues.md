# Audit findings — com.rubickanov.statemachine
Generated by automated review.

## Critical (correctness / bugs)

- **Exception/cancellation during a transition permanently wedges the FSM** — `Runtime.Async/AsyncStateMachine.cs:162-205` (and `:90-115`), `Runtime/StateMachine.cs:153-192` (and `:87-109`) — In `PerformTransitionAsync` the machine sets `_isTransitioning = true` (line 182) and increments `_transitionDepth` (line 169) before awaiting `previousState.OnExitAsync(nextCt)` (line 183) and `nextState.OnEnterAsync(nextCt)` (line 189). These flags are only cleared on the success path (`_isTransitioning = false` at line 190, `_transitionDepth = 0` at line 197). If `OnExitAsync`/`OnEnterAsync` throws — which for the async runtime includes the *documented, expected* `OperationCanceledException` when the passed `CancellationToken` is cancelled (see README "CancellationToken Semantics", and the tests `SetStateAsync_CancelledDuringOnEnterAwait_*` / `SetStateAsync_CancelledDuringOnExitAwait_*`) — the exception propagates out leaving `_isTransitioning` stuck `true` and `_transitionDepth` non-zero. Every subsequent `SetStateAsync` then takes the `if (_isTransitioning)` branch (line 151) and merely queues a pending transition that never runs, and `_transitionDepth` keeps accumulating toward the depth cap. The FSM is permanently unusable after a single cancelled transition, even though cancellation is a first-class feature. `StartAsync` (line 103-104) has the same defect: a throw/cancel during the initial `OnEnterAsync` leaves `_isStarted = true` and `_isTransitioning = true`, so the machine can neither be restarted nor transitioned. The synchronous `StateMachine` has the identical structural flaw if a state's `OnEnter`/`OnExit` throws (`Runtime/StateMachine.cs:171-179`, `:100-102`). The existing tests only assert that the exception propagates — they never assert the machine can recover afterwards, so the bug is uncovered. Fix: wrap the transition body (and the initial enter in `Start`/`StartAsync`) in `try/finally` that resets `_isTransitioning = false`, `_transitionDepth = 0`, and clears any pending transition when an exception escapes, leaving the FSM in a consistent, usable state.

## Minor (conventions / shortcomings)

- **Unused assembly reference** — `Runtime.Async/StateMachine.Async.asmdef:4-7` — The async assembly references `StateMachine.Runtime`, but none of the async runtime sources use any type from it (the async runtime defines its own `IAsyncState`, `AsyncStateBase`, `AsyncCallbackState`, etc., and shares only the namespace, not the assembly). The reference is dead coupling and can be removed; only the `UniTask` reference is actually required.
