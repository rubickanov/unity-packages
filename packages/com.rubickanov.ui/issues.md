## Critical (correctness / bugs)

- **[FIXED]** TooltipManipulator never shows with `delay <= 0` — `UIToolkit/Tooltip/TooltipManipulator.cs:56-68` (with `ShowTooltip` at :87-100) — `OnPointerEnter` calls `CancelScheduledShow()` first, which sets `_cancelled = true`. In the `_delay <= 0f` branch it then calls `ShowTooltip()` directly, but `ShowTooltip` begins with `if (_cancelled) return;`. `_cancelled` is reset to `false` only in the delayed (`_delay > 0`) branch, so for an immediate tooltip it is still `true` and the tooltip is never shown. Any `AddTooltip(..., delay: 0f)` is silently a no-op. Fix: set `_cancelled = false;` before the `ShowTooltip()` call in the immediate branch (or before `CancelScheduledShow()`'s effect is observed).

- **[FIXED]** PopupManipulator never shows with `delay <= 0` — `UIToolkit/Popup/PopupManipulator.cs:41-53` (with `ShowPopup` at :61-68) — identical defect: `OnPointerEnter` runs `CancelScheduledShow()` (sets `_cancelled = true`), then on `_delay <= 0f` calls `ShowPopup()`, which early-returns via `if (_cancelled) return;`. `_cancelled` is only cleared in the delayed branch, so `AttachPopup(..., delay: 0f)` never opens the popup. Fix: reset `_cancelled = false;` in the immediate branch before calling `ShowPopup()`.

## Minor (conventions / shortcomings)

- **README uses IUIService methods that do not exist** — `README.md:82-83, 135-146` — the Quick Start and "Showing and Hiding" examples call `ui.ShowScreen<T>(...)`, `ui.HideScreen<T>()`, `ui.HideScreenAsync<T>()`, `ui.HideAllScreens()`, `ui.ShowPopup<T>(...)`, `ui.HidePopup<T>()`, `ui.HidePopupAsync<T>()`, `ui.HideTopPopup()`, and `ui.HideTopPopupAsync()`. None of these exist on `IUIService`/`UIService`; the real API is `Show<T>`, `Hide<T>`, `HideAsync<T>`, `HideTop`, `HideTopAsync`, `HideAll`, `HideAllAsync` (`Runtime/IUIService.cs:6-19`), and the layer (Screen vs Popup) is fixed at `Register<T>` time, not chosen at show time. The examples will not compile. Fix: rewrite the examples against the actual method names.

- **README references `DialogResult.InputValue` which does not exist** — `README.md:212` — the custom-dialog example reads `result.InputValue`, but `DialogResult` only exposes `ButtonId` and `InputText` (`UIToolkit/DialogResult.cs:5-6`). `InputValue` is a field on `DynamicDialogViewModel`, not on the returned `DialogResult`. The example will not compile. Fix: use `result.InputText`.

- **`UIService.HideAll` fires the visibility callback even when nothing was visible** — `Runtime/UIService.cs:199-211` — `HideAll` unconditionally calls `_onUIVisibilityChanged?.Invoke(false)`, whereas `Hide`, `HideTop`, and `HideTopAsync` only fire it when the stack and active screen are empty, and `HideAllAsync` early-returns when nothing is shown (`Runtime/UIService.cs:213-215`). Calling `HideAll()` while already empty pushes a spurious `false` to the cursor-visibility consumer wired in the README's "Cursor Visibility" section. Fix: guard the callback on having actually hidden something (as `HideAllAsync` does).
