## Minor (conventions / shortcomings)

- **README quick-start snippet won't compile in a player build** — `README.md:38` — The snippet `bool enableFile = !Application.isEditor || EditorPrefs.GetBool("Logging.EnableFileInEditor");` is presented as application-startup code, but `EditorPrefs` lives in the `UnityEditor` namespace and is unavailable in any non-editor assembly/build. The `!Application.isEditor` short-circuit is a runtime guard and does not prevent the compile-time reference error. Wrap the editor branch in `#if UNITY_EDITOR` (or show `enableFile = !Application.isEditor;` for builds) so the documented example actually compiles where a user would paste it.

- **Intercepted Unity logs are echoed back to the editor console as duplicates** — `Runtime/UnityLogInterceptor.cs:56` / `Runtime/LoggerFactoryBuilder.cs:42` — In the editor the factory always registers the `AddZLoggerUnityDebug` provider. `UnityLogInterceptor` forwards every `Application.logMessageReceivedThreaded` event to `_logger.Log(...)` on the `"Unity"` category, which fans out to that provider and calls `Debug.Log` again, so every original `Debug.Log`/`Debug.LogError` shows up a second time in the Unity console (reformatted as `... | Unity | ...`). The `[ThreadStatic] _isForwarding` guard correctly stops *infinite* recursion (the re-emit is synchronous on the same thread), but it does not stop the single duplicate. Consider excluding the `"Unity"` category from the UnityDebug provider, or not registering the interceptor when the UnityDebug provider is active, to avoid noisy double logging in the editor.
