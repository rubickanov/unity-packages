# Audit findings — com.rubickanov.ui.loading

Generated by automated review.

## Minor (conventions / shortcomings)

- **README example calls a non-existent API** — `README.md:21` (and the second block) — The Quick Start shows `await _loadingPipeline.Run(op);`, but the loading pipeline (`ILoadingService` / `LoadingService` in `com.rubickanov.loading`) exposes no `Run` method. The actual entry point is `UniTask<LoadResult> Load(IReadOnlyList<ILoadingOperation> operations, bool waitForInput = false, CancellationToken ct = default)`. The example does not compile against the real API and also misleads on the shape (a list of operations, not a single op). Fix: show e.g. `await _loadingService.Load(new ILoadingOperation[] { op });`.

- **Cancellation checked only after scope is already mutated** — `Runtime/RegisterViewsOperation.cs:64-71` — `Execute` calls `progress.Report(0f)` and `_scopeService.Begin()` before the first `ct.ThrowIfCancellationRequested()` inside the loop. `Begin()` disposes the previously active scene scope and opens a new (empty) one (see `SceneViewScopeService.Begin`). So an `Execute` that is cancelled before it starts still tears down the prior scope and leaves a fresh empty scope behind, then throws — observable in `Execute_CancelledBeforeStart_Throws`. For a no-op cancelled run this destroys still-valid UI state. Fix: call `ct.ThrowIfCancellationRequested()` before `_scopeService.Begin()`.
