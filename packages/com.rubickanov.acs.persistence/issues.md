# Audit findings — com.rubickanov.acs.persistence

Generated by automated review.

## Minor (conventions / shortcomings)

- **`GetCacheStats` doc contradicts its implementation** — `Runtime/Debug/PersistenceDebug.cs:114-140` — The XML summary states `ScannedTypes` "reflects how many aspect types have actually been touched, not how many exist in code," and ties it to the lazily-growing scanner cache. The implementation never reads the scanner cache; it iterates `PersistedKeyRegistry.EnumerateReverseIndex()` and counts canonical entries. That reverse index is built eagerly and registers `Type.FullName` for **every** concrete `IEntityAspect` in loaded assemblies — including aspects with zero `[PersistedState]` fields and aspects never snapshotted. So `ScannedTypes` actually equals the count of all concrete aspect types in code, the exact opposite of the documented contract. Likewise `TotalFields` is computed from `EnumeratePersistedFields`, which counts `[PersistedState]` fields that the scanner would reject (it does not run `TryClassify`), so it can exceed the number of fields that ever enter a snapshot. Fix the doc to describe what is actually counted (all aspect types / all `[PersistedState]`-tagged fields), or change the implementation to reflect the scanner cache it claims to report.

- [x] **Collection bindings wipe live data on a non-null type mismatch** — `Runtime/Bindings/PersistedListBinding.cs:29`, `Runtime/Bindings/PersistedHashSetBinding.cs:27`, `Runtime/Bindings/PersistedDictionaryBinding.cs:27` — `WriteValue` calls `_collection.Clear()` before the `(IEnumerable<T>)value` cast. When restoring a snapshot whose stored value is a non-null but type-mismatched collection (e.g. a JSON deserializer hands back `List<long>` for an `ObservableList<int>` field), the cast throws `InvalidCastException` after the collection has already been cleared. `Restore` catches the exception and continues, but the live collection is left empty. This is asymmetric with `PersistedReactiveBinding.WriteValue` (`Runtime/Bindings/PersistedReactiveBinding.cs:27-31`), which validates before assigning and therefore preserves the existing value on a mismatch — contradicting the restore catch's stated intent ("we surface the mismatch and keep going"). Note this is distinct from the intentional, tested null-clears-collection behavior. Fix by performing the cast (or a snapshot copy of the source) before `Clear()`, so a bad write does not destroy existing state. Fixed: all three bindings now cast `value` to the target `IEnumerable` before `Clear()` (null still clears, as before); regression tests `Restore_Observable{List,Dictionary,HashSet}_TypeMismatch_PreservesLiveCollection` cover each.
