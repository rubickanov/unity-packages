# Audit findings — com.rubickanov.acs.netcode

## Critical (correctness / bugs)

- [x] **Server-auth events double-subscribe on the host across an ownership re-gain** — `Runtime/Replication/EntityReplicator.cs:385` (`OnGainedOwnership` → `SubscribeEventBindingsAsAuthority`). `SubscribeEventBindingsAsAuthority` (`EntityReplicator.Events.cs:92`) routes **server-auth** event bindings into `_disposables` and **owner-auth** ones into `_ownerDisposables`. `OnNetworkSpawn` already subscribed the server-auth events into `_disposables`, and on ownership change only `_ownerDisposables` is disposed (`OnLostOwnership`, line 405). `_disposables` is never torn down or rebuilt between spawn and an ownership change. So on a host (`IsServer == true`) that loses ownership of an entity and later regains it (server hands ownership to a client, then takes it back — common for vehicles/possession), `OnGainedOwnership` re-runs `SubscribeEventBindingsAsAuthority`, which re-subscribes every server-auth `Subject<T>` a second time into `_disposables`. Each subsequent regain adds another subscription, so every `OnNext` on a server-auth `[ReplicatedEvent]` is broadcast N+1 times — silent duplicate (and for `Reliable` events, double-applied) gameplay messages. Fix: in the ownership-transfer path subscribe only owner-auth event bindings (e.g. a dedicated `SubscribeOwnerEventBindings()` that skips `Authority == Server`), leaving the server-auth subscriptions made at spawn untouched. Fixed: added `SubscribeOwnerEventBindings()` (owner-auth only → `_ownerDisposables`); `OnGainedOwnership` now calls it instead of the spawn-time `SubscribeEventBindingsAsAuthority()`. Regression test `HostRegainsOwnership_ThenFiresServerAuthEvent_PeersStillReceiveExactlyOnce` covers the host -> client -> host round-trip.

## Minor (conventions / shortcomings)

- **README claims collections are unsupported, but they are fully replicated** — `README.md:87`. The "Replicating Fields" section states: "Only `ReactiveProperty<T>` … is supported. The scanner rejects `IObservableCollection<T>` fields with a targeted error — use a local subscription + custom RPC for networked collections until native delta support lands." This is stale: the package now has full delta replication for `ObservableList<T>`, `ObservableDictionary<K,V>`, `ObservableHashSet<T>`, and `ObservableFixedSizeRingBuffer<T>` (`ReplicationScanner.cs:97-398`, the `Observable*Binding` types, AOT hints in `AotHints.cs:83-119`, and dedicated tests). A reader following the README would hand-roll RPCs for collections that the package already handles. Update the section to document collection replication.
