## Critical (correctness / bugs)

- [x] **`RentSource` can NullReferenceException when every source is in fade-out limbo** — `Runtime/UnityAudioService.cs:109-131` — When the SFX pool is empty the eviction path does `var oldest = _activeSources.First!; source = oldest.Value;`. But `StopSound(handle, fadeOut > 0)` (line 423-440) removes a source from both `_activeNodes` and `_activeSources` and hands it to `FadeOutAndReclaimAsync`, which only re-enqueues it to the pool *after* the fade completes. During that window the source is neither in `_sfxPool` nor in `_activeSources`. If enough concurrent fade-outs occur (in the extreme, `MaxSfxSources == 1` with a single fading source), `_sfxPool.Count == 0` **and** `_activeSources` is empty, so `_activeSources.First` is `null` and `oldest.Value` throws. Fix: guard for an empty active list (e.g. if both pool and active are empty, create a fresh source or return early with `SoundHandle.Invalid`). Fixed: `RentSource` now has an explicit `_activeSources.Count > 0` branch for eviction and grows a fresh source when both pool and active list are empty. Regression test `PlaySFX_PoolEmptyAndAllSourcesFadingOut_GrowsFreshSourceInsteadOfThrowing`.

## Minor (conventions / shortcomings)

- [x] **Package declares Unity 2022.3 but the API requires 2023.2+** — `package.json:7` / `Runtime/SoundConfig.cs:10`, `Runtime/MusicConfig.cs:10`, `Runtime/UnityAudioService.cs:147` — `UnityEngine.Audio.AudioResource` and the `AudioSource.resource` property were introduced in Unity 2023.2 (Unity 6). The code uses them throughout, so it will not compile on the declared minimum `"unity": "2022.3"`. Bump the declared minimum to the version that actually ships `AudioResource`. Already resolved: `package.json` now declares `"unity": "6000.0"` (Unity 6.0), which ships `AudioResource`.

- [x] **SFX fade-in is not tied to the source watcher, so it can write volume to a recycled source** — `Runtime/UnityAudioService.cs:257-289` — `StartPlayWithFade` launches `FadeInAsync` with `_cts.Token` (service-lifetime) instead of the per-source watcher token from `BeginWatch`. `FadeInAsync` loops on `elapsed < duration` and only checks `source != null`, never `source.isPlaying`. If `fadeIn` is longer than the clip, `ReturnAfterPlayAsync` (which waits on `isPlaying`) returns the source to the pool while `FadeInAsync` is still running; the source can then be re-rented by another `PlaySFX` and the stale `FadeInAsync` keeps overwriting its `volume`. Tie the fade to the source's watcher token (or cancel it in `ReturnSource`/`ReclaimToPool`) so it stops when the source is recycled. Fixed: `BeginWatch` is now called before `StartPlayWithFade` in all three SFX play methods, and the watcher token is threaded into `FadeInAsync`, so `EndWatch` (on return/evict/stop) cancels the fade before it can touch a recycled source.
